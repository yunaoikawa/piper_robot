# 2案の比較と推奨

## 推奨：案A — Learning to Open and Remove

「掴んだ」と「開いた／外れた」は違う、という誰でも理解できる問題から
始める。DoorとCapを同じ状態遷移で説明でき、実写真・開度・角度差・保持運搬の
数値が主張に直接つながる。いまある証拠で最も無理なく読める案。

主張は、ラボのアクセス操作を、物理的失敗から認識・制御・検証を修正して
獲得したこと。一般的な「LLMはツールが使えてすごい」より具体的。
弱点は、繰り返し試行による成功率と比較実験がまだないこと。

## 比較案：案B — RoboEvolve

「方策の外側にあるハーネスも直さないと学習が進まない」を軸にする。
観測接続、実行中断、評価器、回復、記録をハーネスとして定義し、単なる
認識・制御コードと混同しない。変更対応表が中心の方法論寄りの原稿。

ENPIREも環境APIをエージェントが生成するため、「初めて自動生成した」とは
書かない。こちらは人間のフィードバックを伴う、方策・ハーネスの継続改修の
事例として位置づけた。弱点は、ハーネス共進化の優位を独立に測っていないこと。

## どちらを育てるか

今のデータでまず読んでもらうならA。固定ハーネス対改修可能ハーネスの実験を
追加できるならBの方法論的主張が強くなる。2本は同じ実験の別表現なので、
同時に独立した2論文として投稿しない。

今回入れていない主張：breakout forceの計測、ねじ緩め、無菌性、VLAより優位、
ENPIREと同等の性能／低コスト、未知ラボへの汎化。制約を長々と主題にせず、
結果の意味を誤解させない場所にまとめた。

2. 独立に固定した判定器で、既存方策と改善後方策を比較。
3. 案Bなら同一予算の「ハーネス固定／変更可能」を比較。
4. 力学を中心にする場合のみ、時刻同期した力・電流・関節状態・物体運動を取得。
